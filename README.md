# АЛЕФ → АБИС «Светоч»

Приложение оператора миграции библиотечных данных. Самостоятельный проект:
`rsl-abis-service-v2` — соседний бэк АБИС, а не бэк этого приложения.

Первая версия: React + TypeScript в Electron, настройка SSH и PostgreSQL,
пути к серверным выгрузкам нормативных записей RSL10/RSL11 и библиографических
записей RSL01 для связей НЗ–БЗ. Справа — интерактивный терминал системного OpenSSH.

## Запуск

Требуются macOS, Node.js 22.12+ (рекомендуется 24), npm, `/usr/bin/ssh`.
На чистой машине для сборки node-pty могут потребоваться Xcode Command Line Tools.

```bash
npm ci
npm start
```

`npm start` проверяет TypeScript, собирает интерфейс и открывает Electron.
Для работы только над React: `npm run dev`, затем открыть адрес Vite.
В браузере SSH и выбор локального ключа недоступны — об этом сообщается в интерфейсе.

## Что работает

- Настройка сервера, порта, пользователя, выбор приватного SSH-ключа без расширения или `.pem` через системный диалог.
- Настоящий SSH-сеанс с вводом, выводом, изменением размера, очисткой экрана и отключением.
- Проверка подключения к PostgreSQL через действующий SSH: база, пользователь, версия, SSL и время ответа.
- Автосохранение настроек в localStorage; пустые источники используют пути из плейсхолдеров.
- Папка НЗ: проверка контейнера/worker/доставки, подготовка RSL10/RSL11, status/log/report.
- Полный импорт RSL10/RSL11 с переключением библиотеки и независимыми checkpoint: staging → анализ → пробная запись с откатом → запись в public → итоговая проверка; после каждого этапа — подтверждение отчёта.
- Локальное сохранение профиля и пароля БД для конкретного подключения. Пароль в форме скрыт точками; очистка поля удаляет сохранённый пароль.
- Проверка параметров SSH до запуска процесса; ключ сервера проверяет сам OpenSSH.

Выберите **приватный** файл, например `~/.ssh/id_ed25519`, без `.pub`.
Файлы без расширения и `.pem` доступны в диалоге. `.pub` отклоняется с пояснением.
Приватный ключ читает системный SSH; React и Electron не читают его содержимое
и сохраняют только путь. Парольную фразу зашифрованного ключа SSH запросит в терминале.
Заранее загружать ключ в SSH-agent не требуется.

Без выбранного ключа используются стандартные identities и `~/.ssh/config`.
SSH alias разрешён, но поле пользователя и порт задаются явно; введённый порт
имеет приоритет над `ssh/config`. Старое поле профиля `publicKey` игнорируется:
после обновления выберите приватный ключ и сохраните настройки, остальные поля сохраняются.

## Проверка PostgreSQL

После обновления перезапустите приложение и заново откройте SSH. Завершите вход
в терминале, заполните БД и нажмите «Проверить подключение». Адрес БД относится
к серверу SSH, включая `127.0.0.1`. Проверка выполняет только один SELECT
в соединении read-only; права импорта и структура целевой схемы не проверяются.

Используется отдельный TCP-канал OpenSSH в уже аутентифицированной сессии.
Повторного ввода SSH-пароля не нужно, `psql` на сервере не требуется.
SSH-сервер должен разрешать TCP forwarding. Нет локального слушающего порта,
временных файлов с паролем и remote shell-команды с реквизитами БД.

Таймаут всей проверки — 10 секунд, SQL — 5 секунд. Отключение SSH отменяет её.
`disable` отключает TLS внутри SSH; `prefer` сначала пробует TLS и повторяет без
него только после явного ответа PostgreSQL об отсутствии SSL; `require` требует
TLS без проверки сертификата; `verify-full` проверяет сертификат и имя/IP БД.
Для `verify-full` используются доверенные CA локального Node.js, пользовательский
CA и клиентские сертификаты пока не выбираются в интерфейсе.

## Границы версии

Просмотр удалённых каталогов и обработка связей из интерфейса ещё не реализованы. Пути задаются вручную или берутся из подсказок. Заполненные поля не означают
проверенное подключение или существование файлов.

Статус «SSH-сеанс запущен» означает запуск процесса, а успешный вход оператор
проверяет по выводу терминала. Приложение не разбирает shell prompt как статус.
При закрытии или перезагрузке окна SSH завершается. Задачи worker запускаются только по нажатию кнопок и продолжаются независимо от приложения.
Завершение проверяется по task.id, status и exitCode, а не по завершению команды start.

Профиль сохраняется автоматически при редактировании. Кнопка «Сохранить настройки» также доступна. Пароль БД сохраняется локально отдельно для каждого подключения и отображается точками.
Драйвер PostgreSQL получает его на время проверки. История терминала находится только в памяти
(до 5000 строк) и не пишется в файл.

[Нормативные записи: кнопки полного импорта RSL10](docs/authorities-workflow.md).

Приложение не подключается к SSH и не выполняет серверные команды при старте,
открытии папки или изменении настроек. Операции запускает только оператор кнопками.
Разработка и автоматические проверки используют отдельные localhost-стенды,
рабочий сервер не используется.
