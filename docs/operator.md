# Первый запуск

1. Выполнить `npm ci` и `npm start` в каталоге приложения.
2. Ввести SSH-сервер или alias, порт и пользователя.
3. При необходимости выбрать приватный ключ без `.pub`, например `id_ed25519`
   или `server.pem`. Диалог показывает все файлы, включая файлы без расширения.
   `.pub` отклоняется. SSH сам читает приватный ключ и при необходимости запрашивает
   его парольную фразу в терминале; предварительный `ssh-add` не требуется.
   Пустой выбор оставляет стандартные настройки SSH. После обновления старого профиля
   выберите приватный ключ заново: прежнее поле публичного ключа не переносится.
4. Нажать «Открыть SSH». Справа появляется реальный SSH-сеанс. Проверить fingerprint
   сервера перед подтверждением, затем завершить вход в терминале.
5. Для ручной проверки можно ввести `hostname`, `pwd`, `ls`. Эти команды выполняет
   оператор; приложение автоматически их не отправляет.
6. Задать PostgreSQL так, как он доступен с сервера миграции. `127.0.0.1` здесь означает
   сервер, а не компьютер с Electron. Введите пароль и нажмите «Проверить подключение».
   Зелёный результат показывает базу, пользователя, версию PostgreSQL и SSL;
   красный — ошибку. Проверка не меняет данные и не проверяет готовность схемы импорта.
   При ошибке SSH завершите вход в терминале. При запрете forwarding обратитесь
   к администратору SSH-сервера; приложение не меняет серверную конфигурацию.
7. Указать абсолютные серверные пути к `rsl10_z00.dat`, `rsl11_z00.dat`,
   `rsl01_z00.dat` и каталогу результатов. Файлы не загружаются на локальный компьютер.
8. Настройки сохраняются автоматически. Пустые пути источников используют значения плейсхолдеров. Пароль БД останется только до закрытия/перезагрузки окна.

Кнопка «Отключить» завершает локальный SSH. `exit` в терминале завершает удалённый shell.
Код завершения выводится в терминал и уведомление. Ненулевой код может означать
ошибку сети, аутентификации или завершения shell — точная причина находится в выводе SSH.

Раздел «Нормативные записи» теперь управляет командами worker.
[Пошаговый сценарий](authorities-workflow.md): контейнер и worker → процессинг.
Для уже подготовленного пакета RSL10 выбирайте карточку staging/analyze,
а не повторную подготовку исходного DAT. После stage дождитесь completed/exit 0
и прочитайте отчёт; импортный UUID автоматически сохранится отдельно от task.id.
Затем запускайте analyze. Запись в public из приложения пока не выполняется.

После обновления на версию с проверкой БД требуется новое SSH-подключение из
приложения: старый процесс не имеет управляющего сокета. Изменение параметров БД,
пароля или SSH снимает прежний результат. Пароль сохраняется для выбранного SSH/БД-подключения и после перезапуска отображается точками. Очистка поля удаляет сохранённое значение.
