# Первый запуск

1. Выполнить `npm ci` и `npm start` в каталоге приложения.
2. Ввести SSH-сервер или alias, порт и пользователя.
3. При необходимости выбрать публичный `.pub`. Соответствующий приватный ключ
   должен быть загружен в SSH-agent. Пустой выбор оставляет стандартные настройки SSH.
4. Нажать «Открыть SSH». Справа появляется реальный SSH-сеанс. Проверить fingerprint
   сервера перед подтверждением, затем завершить вход в терминале.
5. Для ручной проверки можно ввести `hostname`, `pwd`, `ls`. Эти команды выполняет
   оператор; приложение автоматически их не отправляет.
6. Задать PostgreSQL так, как он доступен с сервера миграции. `127.0.0.1` здесь означает
   сервер, а не компьютер с Electron. SSH-туннель пока не создаётся.
7. Указать абсолютные серверные пути к `rsl10_z00.dat`, `rsl11_z00.dat`,
   `rsl01_z00.dat` и каталогу результатов. Файлы не загружаются на локальный компьютер.
8. Сохранить настройки. Пароль БД останется только до закрытия/перезагрузки окна.

Кнопка «Отключить» завершает локальный SSH. `exit` в терминале завершает удалённый shell.
Код завершения выводится в терминал и уведомление. Ненулевой код может означать
ошибку сети, аутентификации или завершения shell — точная причина находится в выводе SSH.

Следующий этап разработки: отдельный исполнитель операций через SSH с проверкой
состояния серверной задачи, чтением JSON-отчётов и восстановлением наблюдения.
Он должен использовать действующие команды проекта НЗ и связей, а не отправлять
команды кнопок в общий интерактивный shell.
