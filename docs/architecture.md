# Архитектура приложения

React → изолированный preload → Electron main → PTY → системный OpenSSH → сервер.
Обратный путь: PTY → событие IPC → xterm.js. Настройки БД и файлов пока остаются
в форме. Приложение не обращается к бэку `rsl-abis-service-v2`.

<a id="desktop"></a>

## Окно и мост Electron

<details>
<summary>React работает без Node.js<br>Preload предоставляет только методы SSH и выбора ключа<br>Main проверяет отправителя IPC и владеет процессом</summary>

[createWindow](../electron/main.cjs#L9) создаёт единственное окно 1510×980,
минимум 1120×760, загружает локальную production-сборку Vite. Sandbox,
contextIsolation включены, nodeIntegration выключен. Новые окна и навигация
заблокированы. Закрытие окна, перезагрузка или падение renderer завершают локальную сессию.

[assertSender](../electron/main.cjs#L41) проверяет WebContents и главный frame
каждого IPC. Чужой отправитель получает исключение до выполнения операции.

[Мост preload](../electron/preload.cjs#L3) возвращает Promise для выбора ключа,
подключения и отключения. Методы write/resize передают только данные терминала.
Подписки onData/onExit возвращают функции отписки. Renderer не получает общий
ipcRenderer, require, файловую систему или выполнение произвольного локального shell.

Обработчик `key:choose` открывает системный диалог `.pub` в `~/.ssh` с видимыми скрытыми файлами, возвращает путь или null
при отмене. Содержимое ключей не читается приложением. Фильтр диалога не заменяет
валидацию пути при подключении.

</details>

<a id="ssh"></a>

## SSH и жизненный цикл процесса

<details>
<summary>Один локальный SSH-процесс на окно<br>Аргументы передаются массивом без shell<br>Вывод не используется для автоматического определения успешного входа</summary>

[buildSshArgs](../electron/ssh.cjs#L4) принимает объект SshProfile и возвращает
массив аргументов. Проверяет сервер, пользователя, целый порт 1–65535, абсолютный
путь `.pub` без NUL/CR/LF. При дефекте выбрасывает Error, процесс не запускается.
Разрешены DNS, IPv4 и IPv6; экзотические alias с пробелами не поддерживаются.

Используются `-tt`, `StrictHostKeyChecking=ask`, ConnectTimeout=15,
ServerAliveInterval=15, ServerAliveCountMax=3. При выборе публичного ключа добавляются
IdentitiesOnly=yes и `-i <путь.pub>`; приватный ключ предоставляет SSH-agent.
Без выбранного ключа действуют стандартные identities. Пользователь и порт
из формы передаются явно, имеют приоритет над SSH config.

[Обработчик ssh:connect](../electron/main.cjs#L67) сначала проверяет отправителя,
отсутствие активной сессии и параметры, затем запускает `/usr/bin/ssh` через node-pty.
Переменные окружения наследуются, чтобы SSH мог использовать SSH_AUTH_SOCK.
Начальный размер PTY 80×24, затем уточняется терминалом. Возврат `started`
подтверждает создание процесса, а не аутентификацию.

onData пересылает чанки в окно; границы чанка не совпадают с логическими строками.
onExit освобождает сессию и возвращает код завершения. События старого процесса
после его остановки игнорируются, чтобы не повредить новую сессию.

[stopSession](../electron/main.cjs#L50) сначала снимает ссылку, затем завершает PTY.
Вызывается отключением, закрытием окна и выходом из приложения; повторный вызов
без сессии ничего не делает. Серверные длительные задачи пока не запускаются.

Обработчик write принимает строку не более 65536 символов, resize — целые размеры
2–500 столбцов и 1–300 строк. Неверные данные игнорируются; без сессии оба метода
ничего не делают. Будущий исполнитель операций должен иметь отдельный SSH-канал
и структурированные результаты вместо ввода команд в эту PTY.

</details>

<a id="terminal"></a>

## Терминал

<details>
<summary>xterm.js отображает реальный PTY<br>ResizeObserver согласует размеры окна и удалённого терминала<br>История ограничена 5000 строками в памяти</summary>

[TerminalPane](../src/TerminalPane.tsx#L8) получает running и callback onExit.
Первый effect создаёт xterm.js, FitAddon и подписки моста. Ввод пользователя
через onData передаётся в write, события SSH отображаются через term.write.
Код выхода дописывается в терминал и передаётся App. Ref exitHandler обеспечивает
актуальный callback без пересоздания терминала при каждом рендере.

ResizeObserver вызывает fit и resize при изменении контейнера. Cleanup снимает
подписки, отключает observer, освобождает terminal и обработчик ввода; это также
нужно для React StrictMode. Второй effect при открытии сессии ставит фокус,
показывает разделитель и уточняет размер PTY. Очистка экрана не закрывает SSH.

Без preload (браузер Vite) показывается сообщение о доступности SSH только в Electron.
Подтверждение fingerprint и ввод пароля выполняются оператором в терминале.
Приложение не сохраняет терминальный вывод в профиль или файл.

</details>

<a id="profile"></a>

## Профиль и форма

<details>
<summary>Сервер, БД и пути хранятся локально<br>Пароль БД существует только в памяти React<br>Полнота формы не означает успешную проверку подключения</summary>

[loadProfile](../src/App.tsx#L29) читает `svetoch.migration.profile.v1` из localStorage,
накладывает только известные строковые поля на значения по умолчанию. Ошибка JSON,
хранилища или отсутствие профиля возвращают пустой профиль. Циклы проходят группы
и их поля; неизвестные ключи (включая password) не переносятся в результат.

[App](../src/App.tsx#L85) владеет черновиком Profile, отдельным состоянием пароля,
выбранным разделом и состоянием SSH. update меняет поле и снимает флаг сохранения.
save пишет только Profile; пароль не является его полем. Ошибка localStorage
показывается уведомлением. Выбор ключа вызывает preload и меняет путь только
после подтверждения диалога; отмена сохраняет прежнее значение.

connect очищает сообщения, блокирует повторную кнопку на время Promise и открывает
SSH. Ошибка IPC/валидации/запуска показывается как alert; finally снимает busy.
disconnect закрывает SSH и обновляет состояние формы. Callback onExit сбрасывает
running и показывает код выхода. Подключение и вывод остаются доступны независимо
от заполнения параметров БД и файлов.

[Field](../src/App.tsx#L45) группирует подпись, контрол и подсказку;
[SectionTitle](../src/App.tsx#L62) показывает номер, название и пояснение карточки.
Однотипные callbacks onChange передают строку в update, переключатели разделов
меняют представление, закрытие уведомления очищает сообщения. Это UI без
побочных действий на сервере. Состояния «пути заданы» и «параметры заданы»
проверяют заполненность, а не доступность БД и файлов.

</details>

## Ошибки и проверка

| Ситуация                      | След                                       | Поведение                                       |
| ----------------------------- | ------------------------------------------ | ----------------------------------------------- |
| Некорректный SSH-профиль      | Alert с текстом Error                      | Процесс не запущен, можно исправить и повторить |
| SSH завершился                | Код в терминале и уведомлении              | Кнопка подключения доступна снова               |
| Отмена выбора ключа           | Без сообщения                              | Прежний путь сохранён                           |
| Не удалось сохранить профиль  | Alert                                      | Черновик остаётся в памяти                      |
| Повреждённый сохранённый JSON | Пустой профиль                             | Можно заново заполнить настройки                |
| Просмотр в браузере           | Пояснение в терминале и alert при действии | SSH не запускается                              |

Серверных логов, JSON-отчётов, checkpoint и счётчиков записей в этой версии нет.
`npm test` проверяет границы аргументов SSH и отклонение внедрения опций.
`npm run test:desktop` проверяет настоящее окно Electron, изоляцию Node,
сохранение без пароля и ошибку SSH на локальном порту 1. Рабочие серверы не используются.

## Выбор технологий

Electron позволяет локально запускать системный SSH без HTTP-сервиса на localhost;
React отвечает за интерфейс, node-pty — за интерактивную сессию, xterm.js — за её
отображение. Vite собирает локальные статические файлы. Стоимость выбора — размер
Electron и нативная зависимость node-pty. Проверенная целевая платформа первой
версии — macOS; установщики и поддержка других ОС пока не подготовлены.

<a id="pty-install"></a>

## Установка PTY

[scripts/prepare-pty.cjs](../scripts/prepare-pty.cjs#L5) запускается npm postinstall.
У поставляемого node-pty 1.1.0 helper в prebuilds может не иметь executable bit,
что приводит к `posix_spawnp failed` вместо SSH. preparePty на Unix проходит
только build/Release, build/Debug и prebuilds текущей платформы/архитектуры
в каталоге зависимости, добавляет существующему spawn-helper права выполнения.
На Windows ничего не делает. Ошибка изменения прав прерывает установку,
а не скрывается. Это изменение применяется и при чистом npm ci.
